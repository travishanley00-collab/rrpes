Architecture

What the platform actually is

No proprietary runtime, no black-box data format — a standard, well-understood stack your team can evaluate the normal way.

WEB

Web-Based, No Client Install

A Blazor Server application — users open it in a browser. Nothing to package, push, or keep updated across individual workstations.

DB

Single Relational Database

Every module — CRM, estimating, scheduling, production, billing, and every add-on module — reads and writes the same PostgreSQL database. One source of truth, not five exports that drift apart.

MIG

Schema-Managed Migrations

Every schema change ships as a reviewable, reversible migration and is applied deliberately — never a hand-run ALTER TABLE against production.

ACC

Server-Enforced Access Control

The role-based screen access matrix and the PIN gates on sensitive centers are checked server-side — not client-side hiding that a curious user could bypass.

AUD

Full Audit Trail

Every meaningful change across every module writes to an activity log, viewable by date range and printable — a real record, not just recent browser history.

BG

Background Automation Service

A background service checks stage timers once a minute and moves or archives cards on its own when a configured rule is met — no external cron job or scheduled task to babysit.

RT

Real-Time, Multi-User

Everyone works against the same live database with presence shown — no shared spreadsheet lock file, no "who has it open" guessing game.

HOST

Hosting Flexibility

Runs on your own infrastructure or cloud account, or hosted by Rock River Consulting — either way, the database and its backups belong to you.

What to verify before saying yes

The questions an IT reviewer actually asks

1

Where does the data live, and who can get to it directly?

One PostgreSQL database is the single source of truth for the whole platform — your team can connect with any standard PostgreSQL client or reporting tool if direct access is ever needed, and back it up the same way you back up any other database.

2

How do schema changes get applied?

Through EF Core migrations — each one a reviewable file, applied with a deliberate, logged step. Nothing changes the schema silently in the background.

3

Is access control real, or just hidden menus?

The role-based access matrix and the PIN gates on HR, Finance, and Admin centers are checked on the server on every request — not just menu items hidden in the browser.

4

What does an end user actually need on their machine?

A modern browser and network access to wherever the application is hosted — nothing installed, nothing to keep patched on individual workstations.

5

Who hosts it, and what happens if the relationship ends?

You can run it on your own infrastructure from day one, or have Rock River Consulting host it and migrate later — the database is a standard PostgreSQL instance either way, so there's no proprietary export step to worry about.

Requirements

What has to be true on each end

No exotic requirements — a standard web application and a standard database, either self-hosted or hosted for you.

For end users

Device
Any desktop, laptop, or tablet with a modern browser — no OS restriction.
Software
Nothing to install. No plugins, no client app, no updates to push.
Connectivity
Network access to wherever the application is hosted — your LAN/VPN for on-premises hosting, or standard internet access for cloud hosting.

For hosting the application

Runtime
.NET, running as a Blazor Server application — deployable behind IIS, a container, or a standard cloud app-hosting service.
Database
A PostgreSQL database instance — self-hosted, or a managed cloud PostgreSQL service.
Hosting choice
Your own servers or cloud account, or hosted by Rock River Consulting — the database stays a standard PostgreSQL instance either way, so nothing is locked to a proprietary format.
